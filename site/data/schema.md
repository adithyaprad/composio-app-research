# Row schema (short form)

Generated by `scripts/build_site.py` from `schema/app_row.schema.json` and `schema/README.md`. Full definitions and scoring rules live in the repo: https://github.com/adithyaprad/composio-app-research/tree/main/schema

## How to read a row

Each object in `final.json` (one line in `final.csv`) is one app. `verdict` answers "could an agent toolkit be built today?" and `blocker` names the single main reason when it cannot. `access` says how a developer gets credentials from the vendor; `gated_sales` / `gated_partner` with evidence is a correct finding, not a failure. `auth_methods` lists only auth for the product's own API (not MCP-only OAuth or dashboard login), and `primary_auth` is the one a multi-tenant toolkit would build first. Every claim in `evidence` cites a page the agent actually fetched; the quoted snippets are in the repo under `data/runs/pass3/evidence/`. `composio_toolkit` is a catalog lookup, never researched. `confidence` and `notes` carry the caveats.

## Fields

| Field | Type / values | Meaning |
|---|---|---|
| `id` | integer | Stable id from data/apps.csv. |
| `slug` | string | Stable kebab-case slug from data/apps.csv. |
| `name` | string | App name as listed in the research set. |
| `category` | `crm_and_sales` / `support_and_helpdesk` / `communications_and_messaging` / `marketing_ads_email_social` / `ecommerce` / `data_seo_and_scraping` / `developer_infra_and_data` / `productivity_and_project_management` / `finance_and_fintech` / `ai_research_and_media` | Category slug; must match data/apps.csv. |
| `one_liner` | string | What the product does, in one sentence. |
| `auth_methods` | list of `oauth2` / `api_key` / `basic` / `jwt_service_account` / `custom_other` / `none` / `unknown` | All documented ways to authenticate requests to the product's own developer API. |
| `primary_auth` | `oauth2` / `api_key` / `basic` / `jwt_service_account` / `custom_other` / `none` / `unknown` | The API auth method a multi-tenant agent toolkit would implement first. |
| `access` | `self_serve` / `self_serve_paid` / `gated_partner` / `gated_sales` / `no_public_api` | How a developer obtains API credentials from the vendor. |
| `api_types` | list of `rest` / `graphql` / `soap` / `sdk_only` / `webhook_only` / `cli_only` / `none` | Documented API styles. |
| `has_public_docs` | boolean | True if official public API or developer docs exist. |
| `api_breadth` | `narrow` / `moderate` / `broad` / `unknown` | Rough useful surface area, not a precise endpoint count. |
| `docs_url` | string or null | Best official docs entry point. |
| `mcp_status` | `official` / `community` / `none` | Whether an MCP server exists. |
| `mcp_url` | string or null | URL of the MCP server, repo, or official announcement. |
| `verdict` | `buildable_now` / `buildable_with_approval` / `not_buildable` | could this be an agent toolkit today? |
| `blocker` | `none` / `no_public_api` / `gated_access` / `auth_undocumented` / `docs_insufficient` / `api_too_narrow` / `terms_restrict_automation` / `preview_or_unstable` / `other` | Main reason the app is not buildable_now. |
| `evidence` | object | Per claim (`auth`, `access`, `api_surface`, `mcp`, `verdict`; optional `one_liner`): a list of `{url, source_type, note}`. |
| `confidence` | `high` / `medium` / `low` | Overall confidence in the row, driven by evidence quality. |
| `requires_end_user_admin` | boolean | True when a customer workspace/org admin must approve install. |
| `notes` | string | Caveats, secondary blockers, or ambiguity. |
| `composio_toolkit` | object | Catalog lookup: `status` (`exists` / `none` / `unknown`), `toolkit_slug`, `sibling_slugs`, `checked_at`, `evidence_url`. |

## `access` values

| Value | Meaning |
|---|---|
| `self_serve` | A developer can create an account and get credentials alone, for free or on a trial, with no sales conversation. |
| `self_serve_paid` | Same, but API access requires a paid plan the developer can buy without talking to sales, and with no human vendor review. |
| `gated_partner` | Usable credentials, or permission to call the API as a third-party / multi-tenant app, require manual vendor review: a partner program, app review, developer-profile approval, or a mandatory app-store listing (e.g. |
| `gated_sales` | Credentials require contacting sales, an enterprise contract, a waitlist, or manual vendor approval that is not a self-serve checkout. |
| `no_public_api` | No documented public API a third-party developer can call. |

## `verdict` values

| Value | Meaning |
|---|---|
| `buildable_now` | A documented callable interface and a self-serve path (`self_serve` or `self_serve_paid`) exist, so a toolkit or skill could be built today. |
| `buildable_with_approval` | A documented interface exists, but credentials or listing require partner, sales, or vendor approval first. |
| `not_buildable` | No usable public interface, terms forbid this kind of automation, or docs/auth are too incomplete to implement against. |

## `blocker` values

| Value | Meaning |
|---|---|
| `none` | No blocker. |
| `no_public_api` | No documented public interface. |
| `gated_access` | Partner/sales/approval gate is the main thing in the way. |
| `auth_undocumented` | An API may exist, but auth is not documented well enough to implement. |
| `docs_insufficient` | Auth may be known, but the API is not documented well enough to implement. |
| `api_too_narrow` | The interface exists but is too thin to be a useful toolkit (e.g. |
| `terms_restrict_automation` | Terms of use or policy forbid bots, scraping, or third-party agent access. |
| `preview_or_unstable` | Only an alpha/beta or unstable preview exists. |
| `other` | Anything else; `notes` must explain. |

## `mcp_status` values

| Value | Meaning |
|---|---|
| `official` | Published or endorsed by the vendor (listed in their docs, official repo, or official announcement). |
| `community` | A third-party server only (GitHub, directories, blogs). |
| `none` | No usable MCP server found. |
